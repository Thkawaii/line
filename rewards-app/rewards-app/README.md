# ระบบสะสมคะแนนพนักงาน (Community Web Application)

เว็บแอปสะสมคะแนนและแลกของรางวัลสำหรับพนักงาน พัฒนาตามไฟล์ออกแบบ Figma ที่ส่งมา
แบ่งเป็นสองฝั่งในโปรเจคเดียว

- **ฝั่งพนักงาน** ออกแบบมาเพื่อมือถือ จำกัดความกว้าง 480px และจัดกลางเมื่อเปิดบนจอใหญ่
- **ฝั่งผู้ดูแลระบบ** แดชบอร์ดเต็มจอ มีเมนูข้างแบบย่อได้ และย่อลงเป็นแถบนำทางล่างบนจอเล็ก

| ส่วน | เทคโนโลยี |
| --- | --- |
| หน้าบ้าน | React 18 + Vite 5 + Tailwind CSS 3 + React Router 6 |
| หลังบ้าน | Go 1.22 + net/http + PostgreSQL (ไดรเวอร์ `lib/pq`) |
| ยืนยันตัวตน | JWT (HS256) อายุ 7 วัน รหัสผ่านแฮชด้วย PBKDF2-HMAC-SHA256 |
| QR | สร้างฝั่งเบราว์เซอร์ด้วย `qrcode` |

## เริ่มใช้งาน

ต้องมี Go 1.22 ขึ้นไป (สำหรับ backend), Node.js 18 ขึ้นไป (สำหรับหน้าเว็บ) และ PostgreSQL 14 ขึ้นไป

### 1. ฐานข้อมูล

ระบบใช้ฐานข้อมูลชื่อ **line** และจะสร้างให้อัตโนมัติตอนสั่ง `go run ./cmd/migrate`
ขอแค่มี PostgreSQL เปิดอยู่และบัญชีที่ใช้มีสิทธิ์สร้างฐานข้อมูล

**ถ้ามี Docker** สั่งทีเดียวจบ ค่าตรงกับ `.env.example` อยู่แล้ว

```bash
docker compose up -d
```

**ถ้าติดตั้ง PostgreSQL ไว้ในเครื่องเอง** ไม่ต้องสร้างฐานข้อมูลเอง แค่เปิด service
ให้ทำงานอยู่ แล้วแก้รหัสผ่านใน `backend/.env` ให้ตรงกับของเครื่องคุณ

```
DATABASE_URL=postgres://postgres:รหัสผ่านของคุณ@localhost:5432/line
```

ตรวจว่าต่อติดไหมด้วย `go run ./cmd/check` ในโฟลเดอร์ `backend` — ถ้าต่อไม่ได้
มันจะบอกสาเหตุและวิธีแก้ให้เลย

### 2. หลังบ้าน

```bash
cd backend
cp .env.example .env          # แก้ DATABASE_URL ให้ตรงกับรหัสผ่าน PostgreSQL ของคุณ
go run .                      # http://localhost:4007
```

**แค่นี้พอ** ตอนเปิดเซิร์ฟเวอร์ระบบจะเตรียมฐานข้อมูลให้เอง

1. ยังไม่มีฐานข้อมูล `line` → สร้างให้
2. ยังไม่มีตาราง → สร้างตารางและบัญชีตั้งต้นให้
3. มีตารางอยู่แล้ว → ไม่แตะอะไรเลย ข้อมูลที่ใช้งานอยู่ปลอดภัย

คำสั่งเสริมที่ปกติไม่ต้องใช้

```bash
go run ./cmd/check            # ตรวจการเชื่อมต่อฐานข้อมูล ใช้ตอนเจอปัญหา
go run ./cmd/demo             # ใส่ข้อมูลทดสอบพร้อมรูป ครบทุกรูปแบบ
go run ./cmd/demo clear       # ลบข้อมูลทดสอบทิ้ง
go run ./cmd/seed             # สร้างบัญชีตั้งต้นคืน เผื่อเผลอลบทิ้ง
go run ./cmd/migrate          # ล้างทุกตารางแล้วสร้างใหม่ — ข้อมูลเดิมหายหมด
```

### ข้อมูลทดสอบ

`go run ./cmd/demo` ใส่ของรางวัล กิจกรรม แบนเนอร์ และคำถามพร้อมรูปภาพให้ทันที
รูปอยู่ที่ `backend/db/demo/` และจะถูกคัดลอกเข้าโฟลเดอร์ `uploads` ให้เอง

ของรางวัลครอบคลุมทุกเคสที่หน้าเว็บต้องรับมือ — มีส่วนลด, ของหมด, เฉพาะ Silver,
เฉพาะ Elite, กิจกรรมพิเศษเหลือ 5 วัน, วันสุดท้าย, ยังไม่ถึงวันเริ่ม, หมดเขตแล้ว,
ซ่อนไว้ และของที่ยังไม่ใส่รูป ส่วนกิจกรรมมีทั้งแบบลงทะเบียน แบบโหวต แบบไม่จำกัดจำนวน
แบบไม่มีรูป และแบบปิดรับแล้ว กิจกรรมตั้งวันเริ่มและวันสิ้นสุดได้ สำหรับงานที่จัดหลายวัน

พนักงาน `1875` จะได้ 3,200 คะแนนและเลื่อนเป็นระดับ Silver เพื่อให้เห็นทั้งของที่แลกได้
และของที่ระดับยังไม่ถึง

บน Windows PowerShell ใช้คำสั่งเดียวกันได้ทั้งหมด

### 3. หน้าบ้าน

```bash
cd frontend
npm install
npm run dev                   # http://localhost:4008
```

ตอน dev คำขอที่ขึ้นต้นด้วย `/api` จะถูก proxy ไปพอร์ต 4007 ให้อัตโนมัติ ไม่ต้องตั้ง CORS เพิ่ม

### เปิดจากมือถือหรือเครื่องอื่นในวงแลน

vite ผูกกับ `0.0.0.0` อยู่แล้ว เครื่องอื่นเปิด `http://<IP เครื่องคุณ>:4008` ได้ทันที
แต่ถ้าจะใช้ **หน้าสแกน QR** ต้องรันแบบ https แทน เพราะเบราว์เซอร์ให้ใช้กล้องเฉพาะบน
https หรือ localhost เท่านั้น

```bash
npm run dev:https             # https://<IP เครื่องคุณ>:4008
```

ใบรับรองเป็นแบบ self-signed เบราว์เซอร์จะเตือนครั้งแรก กด "ไปต่อ" ได้

## พอร์ตที่ใช้

| พอร์ต | ใช้ทำอะไร |
| --- | --- |
| 4007 | API (Go) |
| 4008 | หน้าเว็บ — ตอน dev คือ vite ตอน production คือ nginx |
| 5432 | PostgreSQL (เปิดเฉพาะตอน dev) — ฐานข้อมูลชื่อ `line` |

เปลี่ยนพอร์ตได้ที่ `backend/.env` (ตัวแปร `PORT`) และ `frontend/vite.config.js`

## ขึ้น server จริงด้วย Docker

```bash
cp rewards.env.example rewards.env        # แก้รหัสผ่านและ JWT_SECRET
# สร้างใบรับรอง https ตามขั้นตอนใน certs/README.md
docker compose -f docker-compose.prod.yml up -d --build

# ครั้งแรกต้องสร้างตารางและใส่ข้อมูลตั้งต้น
docker compose -f docker-compose.prod.yml exec backend /app/rewards-migrate
docker compose -f docker-compose.prod.yml exec backend /app/rewards-seed
```

ผู้ใช้เข้าที่ `https://<IP ของเครื่อง server>:4008`

เปิดออกนอกเครื่องแค่พอร์ต 4008 เท่านั้น ส่วน backend กับ PostgreSQL คุยกันภายใน docker
(backend เปิดที่ `127.0.0.1:4007` ไว้ให้ไล่ปัญหาด้วย curl จากในเครื่อง server ได้)

## ข้อจำกัดที่ควรรู้

หน้าสแกน QR ฝั่งพนักงานเปิดกล้องจริงด้วย `getUserMedia` และอ่านโค้ดด้วย `BarcodeDetector`
ที่มากับเบราว์เซอร์ ซึ่ง Chrome และ Edge บน Android รองรับ แต่ Safari บน iOS ยังไม่รองรับ
หน้าจะแสดงภาพกล้องได้ตามปกติ พร้อมบอกให้ใช้วิธีเลือกรูปจากอัลบั้มหรือกรอกรหัสแทน
ถ้าต้องรองรับ iOS ให้เพิ่มไลบรารีถอดรหัสฝั่งเบราว์เซอร์ เช่น `jsqr` หรือ `zxing-js`
การเปิดกล้องต้องรันผ่าน https หรือ localhost เท่านั้น

แบนเนอร์หน้าแรกอัปโหลดรูปได้แล้ว มีตัวครอปในตัว ไฟล์เก็บที่โฟลเดอร์ `backend/uploads`
และเสิร์ฟผ่านเส้นทาง `/uploads/` (ตอน dev vite ส่งต่อให้ ตอน production nginx ส่งต่อให้)
ขึ้น production ด้วย docker ไฟล์จะถูกเก็บใน volume ชื่อ `uploads` จึงไม่หายตอน deploy ใหม่

ของรางวัลก็อัปโหลดรูปได้เช่นกัน ใช้ตัวครอปตัวเดียวกันแต่ล็อกสัดส่วนไว้ที่ 4:3 ตามกรอบรูปในการ์ด
ส่วนรูปกิจกรรมยังเป็นบล็อกสีเทา ฐานข้อมูลมีคอลัมน์ `image_url` รออยู่แล้ว ต่อตัวอัปโหลดเดียวกันได้ทันที

เทมเพลตในแท็บ Systems Event เปิดปิดและเลือกช่องทางได้จริง แต่ตัวจับเวลาที่จะยิงแจ้งเตือนอัตโนมัติ
(เช่น เตือนก่อนคะแนนหมดอายุ) ยังต้องต่อ cron หรือ job scheduler เพิ่มเอง

## ข้อมูลตั้งต้น

`go run ./cmd/seed` **ไม่ได้ใส่ข้อมูลตัวอย่างแล้ว** สร้างให้เฉพาะสิ่งที่ระบบต้องมีจึงจะทำงานได้

| สิ่งที่สร้างให้ | เหตุผล |
| --- | --- |
| พนักงาน `1875` / `2962` และแอดมิน `admin` / `line` | บัญชีสำหรับเข้าใช้งานครั้งแรก |
| ระดับสมาชิก Member / Silver / Elite | ระบบใช้เกณฑ์คะแนนและตัวคูณจากตารางนี้ ถ้าว่างจะเลื่อนระดับไม่ได้ |
| ค่าตั้งระบบ และรายการแจ้งเตือนอัตโนมัติ | ระบบอ่านค่าจากตารางนี้ เช่น อายุ QR |
| เอกสารข้อกำหนดและนโยบาย PDPA | พนักงานต้องกดยอมรับก่อนเข้าใช้ครั้งแรก ถ้าไม่มีเอกสารจะเข้าใช้ไม่ได้ |

ของรางวัล กิจกรรม แบนเนอร์ และคำถามที่พบบ่อย **ว่างเปล่า** ให้ผู้ดูแลระบบกรอกเองจากหน้าแอดมิน
คำสั่งนี้สั่งซ้ำได้ ข้อมูลที่มีอยู่แล้วจะไม่ถูกเขียนทับ

## คะแนนและระดับสมาชิก

| ระดับ | เกณฑ์คะแนน | ตัวคูณ | คะแนนที่ต้องใช้ในรอบปีเพื่อคงระดับ |
| --- | --- | --- | --- |
| Member | 0 | x1.0 | — |
| Silver | 1,000 | x1.5 | 500 |

**ตัดยอดคะแนนประจำปี** ระบบทำให้เองเมื่อถึงวันที่ตั้งไว้ในหน้า System Settings
(ค่าเริ่มต้น 31 ธันวาคม) ผู้ดูแลไม่ต้องกดเอง แต่กดสั่งเองได้จากหน้าจัดการคะแนน

**คะแนนกลับเป็น 0 ทุกคนเท่ากัน** สิ่งที่ต่างกันคือระดับที่รักษาไว้ได้

| ระดับเดิม | คะแนนที่ใช้แลกในรอบปี | ระดับหลังรีเซ็ต | คะแนนหลังรีเซ็ต |
| --- | --- | --- | --- |
| Member | ไม่กำหนด | Member | 0 |
| Silver | ตั้งแต่ 500 | Silver | 0 |
| Silver | ต่ำกว่า 500 | Member | 0 |
| Elite | ตั้งแต่ 1,000 | Elite | 0 |
| Elite | ต่ำกว่า 1,000 | Silver | 0 |

เงื่อนไขคงระดับดูจาก **คะแนนที่ใช้ไป** ไม่ใช่คะแนนคงเหลือ เพราะคนที่แลกของบ่อยคือคนที่ใช้งานจริง
ถ้าวัดจากคะแนนคงเหลือ คนที่เก็บคะแนนไว้เฉย ๆ จะได้เปรียบคนที่แลกของ ซึ่งกลับด้านกับที่ควรเป็น

ตัวตั้งเวลาอยู่ในโปรแกรม ตรวจทุกชั่วโมง และจำปีที่ตัดยอดไปแล้ว จึงไม่ตัดซ้ำ
แม้เปิดเซิร์ฟเวอร์หลายตัวหรือผู้ดูแลกดเองไปก่อนแล้ว

## เงื่อนไขของรางวัล

**ระดับขั้นต่ำ** ตั้งได้ว่าของรางวัลชิ้นนี้ต้องเป็นสมาชิกระดับไหนขึ้นไปจึงแลกได้
พนักงานระดับต่ำกว่ายังเห็นของรางวัลอยู่ แต่รูปจะถูกคลุมด้วยกุญแจและปุ่มเปลี่ยนเป็น
"ปลดล็อกเมื่อถึง …" ฝั่งเซิร์ฟเวอร์ตรวจซ้ำอีกชั้น ต่อให้ยิงตรงมาที่ API ก็แลกไม่ได้

**ช่วงเวลาแลก** ตั้งวันเริ่มและวันสิ้นสุดได้ สำหรับของรางวัลกิจกรรมพิเศษ
ของที่มีกำหนดจะมีป้าย "กิจกรรมพิเศษ" และนับถอยหลัง "เหลือเวลาแลกอีก N วัน"
**พ้นกำหนดแล้วระบบซ่อนจากหน้าพนักงานเองทันที ไม่ต้องรอผู้ดูแลปิด** และแลกไม่ได้
ส่วนหน้าแอดมินยังเห็นครบทุกชิ้นพร้อมสถานะ live / scheduled / expired

## หลายภาษา (ฝั่งพนักงานเท่านั้น)

ฝั่งพนักงานรองรับ **ไทย / English / 日本語** เปลี่ยนได้จากปุ่มโลกมุมซ้ายบนของหน้าหลัก
และที่มุมขวาบนของหน้าเข้าสู่ระบบ เลือกแล้วเปลี่ยนทันทีและจำไว้ให้ครั้งถัดไป
ค่าเริ่มต้นคือภาษาไทย

| ไฟล์ | หน้าที่ |
| --- | --- |
| `frontend/src/lib/i18n.jsx` | ตัวจัดการภาษาและฟังก์ชัน `t()` |
| `frontend/src/lib/locales/th.js` | ข้อความภาษาไทย ใช้เป็นต้นฉบับ |
| `frontend/src/lib/locales/en.js` · `ja.js` | คำแปล ต้องมีคีย์ครบเท่าไฟล์ไทย |
| `frontend/src/lib/format.js` | วันที่และเวลา ไทยใช้ พ.ศ. อังกฤษกับญี่ปุ่นใช้ ค.ศ. |

เพิ่มข้อความใหม่ให้ใส่คีย์ในทั้งสามไฟล์ แล้วเรียกด้วย `t('ชื่อคีย์')`
ตัวแปรในข้อความเขียนเป็น `{{ชื่อตัวแปร}}` แล้วส่งค่าเป็นอาร์กิวเมนต์ที่สอง

### ข้อมูลที่ผู้ดูแลกรอกเองก็แปลได้

ชื่อของรางวัล ชื่อกิจกรรม สิทธิประโยชน์ FAQ ข้อกำหนด และชื่อแบนเนอร์ กรอกคำแปลได้ 3 ภาษา
**ผู้ดูแลระบบกรอกภาษาไทยอย่างเดียว** ฟอร์มในหน้าจัดการไม่มีแท็บเลือกภาษา

- ภาษาไทยเก็บในคอลัมน์ปกติของตาราง (`title`, `name`, ...)
- คอลัมน์ `translations` สำหรับเก็บคำแปลยังอยู่ และ API ยังเอาคำแปลมาทับให้ถ้ามี
  แต่ตอนนี้ไม่มีหน้าจอให้กรอก จึงมีคำแปลเฉพาะที่ระบบใส่มาให้ (ระดับสมาชิกและเอกสารข้อกำหนด)
- **ช่องไหนไม่มีคำแปล หน้าเว็บจะแสดงภาษาไทยแทน** ผู้ใช้จึงไม่เจอช่องว่าง
- ถ้าภายหลังอยากกรอกคำแปลเอง เพิ่มแท็บกลับมาที่ `frontend/src/components/TranslatedFields.jsx`
  ไฟล์เดียว ฝั่งหลังบ้านรองรับอยู่แล้ว

หน้าเว็บฝั่งพนักงานส่งภาษาที่เลือกไปกับทุกคำขอ (`?lang=en`) และ API เอาคำแปลมาทับให้
ตารางที่รองรับ: `events`, `rewards`, `tiers`, `faqs`, `policies`, `banners`

**ยังไม่แปล** ชื่อของรางวัล ชื่อกิจกรรม คำถามที่พบบ่อย และข้อความในประวัติคะแนนกับการแจ้งเตือน เพราะถูกสร้างเป็นภาษาไทยตอนที่เกิดรายการ
และเก็บเป็นข้อความสำเร็จรูปในฐานข้อมูล ถ้าต้องการให้แปลด้วย ต้องเปลี่ยนไปเก็บเป็นรหัสเหตุการณ์
แล้วประกอบข้อความตอนแสดงผลแทน **ฝั่งแอดมินทั้งหมดยังเป็นภาษาไทยอย่างเดียว**

## การรองรับมือถือ

- เลย์เอาต์ทุกหน้าเขียนแบบ mobile-first
- เผื่อระยะ `env(safe-area-inset-*)` ให้เครื่องที่มีรอยบากและแถบล่าง
- ปุ่มและช่องกรอกสูงอย่างน้อย 44px ฟอนต์ช่องกรอก 15px เพื่อไม่ให้ iOS ซูมเอง
- ชิปตัวกรองเลื่อนแนวนอนได้ ซ่อนแถบเลื่อนไว้
- มีขอบโฟกัสที่มองเห็นชัดสำหรับคนใช้คีย์บอร์ด และเคารพ `prefers-reduced-motion`
- ตารางฝั่งแอดมินเลื่อนแนวนอนในกรอบของตัวเอง หน้าเว็บจึงไม่เลื่อนออกด้านข้าง

## หมายเหตุการพัฒนา

- การแลกของรางวัลและการเช็คอินทำงานใน transaction เดียว ล็อกแถวด้วย `FOR UPDATE`
  เพื่อกันคะแนนติดลบและกันแลกของเกินสต็อกเมื่อมีคนกดพร้อมกัน
- ทุกการได้และใช้คะแนนถูกบันทึกลง `point_transactions` ส่วน `users.points` เป็นยอดสรุป
  ตรวจยอดย้อนหลังได้จากตารางเดินบัญชี
- backend ใช้ `net/http` ของ Go ล้วน ไม่ได้ใช้เฟรมเวิร์ก เส้นทางทั้งหมดลงทะเบียนกับ `ServeMux`
  ของ Go 1.22 ที่ระบุ method และ path parameter ได้ในตัว
- รหัสผ่านแฮชด้วย PBKDF2-HMAC-SHA256 (210,000 รอบ ตามที่ OWASP แนะนำ) ซึ่งประกอบจาก
  `crypto/hmac` กับ `crypto/sha256` ที่มากับ Go จึงไม่ต้องพึ่ง `golang.org/x/crypto`
  ทำให้ build ได้แม้ในเครือข่ายที่ดึงโมดูลนั้นไม่ได้
- JWT เป็น HS256 มาตรฐานเดียวกับฝั่ง Node จึงใช้แทนกันได้
- คะแนนที่ได้จากกิจกรรมถูกคูณด้วย `multiplier` ของระดับที่พนักงานอยู่ ณ ตอนนั้น
  (Member x1.0, Silver x1.5, Elite x2.0 ตามค่าเริ่มต้น) ทุกจุดที่จ่ายคะแนนเรียกผ่าน `awardPoints`
  ตัวเดียวกัน จึงไม่มีทางที่บางเส้นทางจะลืมคูณ ส่วนการปรับคะแนนด้วยมือของผู้ดูแลไม่คูณ
- ระดับสมาชิกเลื่อนขึ้นอัตโนมัติทันทีที่คะแนนถึงเกณฑ์ และมีแจ้งเตือนให้พนักงาน
  นอกจากตอนได้คะแนนแล้ว ระบบยังตรวจซ้ำตอนเข้าสู่ระบบและตอนเปิดหน้าแรก
  เผื่อคะแนนถูกแก้จากทางอื่น เช่น แก้ตรงในฐานข้อมูลหรือย้ายข้อมูลมาจากระบบเดิม
  การได้คะแนนและการแลกของรางวัล**เลื่อนขึ้นอย่างเดียว ไม่ลดระดับ** เพราะคะแนนจะลดทุกครั้งที่แลกของ
  ถ้าลดตามคะแนนคงเหลือ พนักงานจะหลุดระดับทันทีที่ใช้คะแนน
- ส่วน**การปรับคะแนนด้วยมือของผู้ดูแลระบบจะคิดระดับใหม่ทั้งขึ้นและลง** เพราะเป็นการแก้ข้อมูล
  โดยตั้งใจ ผลลัพธ์จึงควรสะท้อนคะแนนที่แก้ทันที (เช่น 2,100 ปรับลง 200 เหลือ 1,900 จะกลับเป็น Member)
- ทุกการกระทำสำคัญของผู้ดูแลระบบถูกบันทึกลง `audit_logs` ผ่านตัวช่วย `logAudit`
  ซึ่งตั้งใจให้ล้มเหลวเงียบ ๆ เพราะการบันทึกไม่ควรทำให้งานหลักพัง
- เกณฑ์ระดับสมาชิกและค่าตั้งต่าง ๆ อ่านจากตาราง `tiers` และ `settings` ไม่ได้ฝังไว้ในโค้ด
  แอดมินแก้แล้วมีผลกับฝั่งพนักงานทันที
- โทเค็นเก็บใน localStorage เพื่อความง่ายของเดโม ก่อนขึ้นใช้งานจริงควรย้ายไป httpOnly cookie
  และเพิ่ม rate limit ที่เส้นทางล็อกอิน

## ขึ้น production แบบไม่ใช้ Docker

```bash
cd frontend && npm run build      # ได้ไฟล์ static ที่ frontend/dist
cd ../backend && go build -o rewards . && ./rewards   # API ที่พอร์ต 4007
```

เอา `frontend/dist` ไปเสิร์ฟด้วย nginx โดยใช้ `frontend/nginx.prod.conf` เป็นต้นแบบ
(แก้ `proxy_pass` จาก `http://backend:4007` เป็น `http://127.0.0.1:4007`)

ถ้าหน้าเว็บกับ API อยู่คนละ origin ให้ตั้ง `VITE_API_URL` ก่อน build และตั้ง `CLIENT_ORIGIN`
ฝั่งเซิร์ฟเวอร์ให้ตรงกับโดเมนหน้าเว็บ อย่าลืมเปลี่ยน `JWT_SECRET` ด้วย

## เจอปัญหาตอนรัน

### หน้าเว็บไม่ขึ้นเลย

- เปิดให้ถูก protocol — `npm run dev` คือ **http** ไม่ใช่ https
  ถ้าพิมพ์ `https://localhost:4008` ขณะรันโหมด http หน้าจะว่างเปล่าหรือขึ้น error ทันที
- ดูบรรทัดที่ vite พิมพ์ออกมา มันบอก URL ที่ถูกต้องอยู่แล้ว
- ถ้าขึ้น `Port 4008 is already in use` แปลว่ามีอะไรจองพอร์ตอยู่
  หาแล้วปิดด้วย `netstat -ano | findstr :4008` แล้ว `taskkill /PID <เลข> /F`
- ถ้าขึ้น `Cannot find package` แปลว่ายังไม่ได้ `npm install` ในโฟลเดอร์นั้น

### หน้าเว็บขึ้น แต่ล็อกอินไม่ได้ / ข้อมูลไม่มา

แปลว่า backend หรือฐานข้อมูลมีปัญหา ไล่ตามนี้

```bash
cd backend
go run ./cmd/check            # บอกเลยว่าติดตรงไหน
```

- `ต่อ PostgreSQL ไม่ได้` → PostgreSQL ยังไม่ได้เปิด หรือพอร์ตไม่ตรง
- `ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง` → แก้ `DATABASE_URL` ใน `backend/.env`
- `ยังไม่มีฐานข้อมูลชื่อนี้` → สั่ง `go run ./cmd/migrate` ระบบจะสร้างให้เอง
- `บัญชีนี้ไม่มีสิทธิ์สร้างฐานข้อมูล` → ใช้บัญชี `postgres` หรือสั่ง `ALTER ROLE ชื่อผู้ใช้ CREATEDB;`
- `ยังไม่มีตาราง` → ปกติ `go run .` สร้างให้เองอยู่แล้ว ถ้ายังไม่มีให้สั่ง `go run ./cmd/migrate`

เวลาเปิด backend มันจะพิมพ์สถานะฐานข้อมูลให้ดูทุกครั้ง ถ้าเห็นบรรทัดขึ้นต้นด้วย `⚠`
แปลว่าต่อฐานข้อมูลไม่ได้ ตัว API จะยังเปิดอยู่แต่ทุกหน้าจะดึงข้อมูลไม่ได้

### ตรวจว่า backend ทำงานจริงไหม

```bash
curl http://localhost:4007/api/health
```

ควรได้ `{"ok":true}` ถ้าไม่ได้แปลว่า backend ยังไม่ได้รันหรือรันคนละพอร์ต
